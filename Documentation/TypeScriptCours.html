Guide d'apprentissage TypeScript

De débutant à avancé — du JavaScript typé à la POO moderne

🔷 Qu'est-ce que TypeScript ?

TypeScript est un langage open-source développé par Microsoft (créé par Anders Hejlsberg en 2012). C'est un sur-ensemble de JavaScript : tout code JS valide est du TS valide.

Sa particularité : il ajoute un système de types statiques qui vérifie ton code avant l'exécution. 

TypeScript  ──(compilation)──►  JavaScript
   (.ts)                          (.js)
💡 À retenir Le navigateur et Node.js ne comprennent pas TypeScript directement. Le code .ts doit être compilé en JavaScript exécutable.

Exemple simple

JavaScript

function addition(a, b) {
  return a + b;
}
addition(5, "10"); // ⚠️ "510" — bug silencieux

TypeScript

function addition(a: number, b: number): number {
  return a + b;
}
addition(5, "10"); // ❌ Erreur détectée AVANT l'exécution

🔷 Pourquoi utiliser TypeScript ?

✅ Les avantages

  1. Détecter les erreurs avant l'exécution — bugs de type attrapés à la compilation.
  2. Meilleure autocomplétion — IntelliSense précis dans VS Code.
  3. Refactoring sûr — l'IDE signale tous les endroits à modifier.
  4. Code auto-documenté — les types racontent l'intention.
  5. Idéal en équipe — contrats clairs, moins de régressions.
  6. Adopté massivement — Angular, React, Vue 3, NestJS, Vite…
  7. Migration progressive — on peut typer petit à petit.

⚠️ Les inconvénients

InconvénientDétail
Étape de compilationAjoute un build (léger avec Vite/esbuild)
Courbe d'apprentissageGénériques et types avancés = complexes
Faux sentiment de sécuritéTypes disparaissent à l'exécution → valider les données externes (Zod, Yup)
VerbositéPlus de code à écrire au début
⚠️ Important Les types TS n'existent pas à l'exécution. Pour valider des données externes (API, formulaires), il faut des outils comme Zod, Yup ou io-ts.

🔷 Plan d'apprentissage (6-10 semaines)

📅 Phase 1 — Fondations (Semaine 1-2)

  • Introduction, installation, compilation (tsc)
  • Types de base : string, number, boolean, null, undefined
  • any, unknown, never, void
  • Tableaux, tuples, objets, enum
  • Fonctions typées
  • Interfaces & types

📅 Phase 2 — Intermédiaire (Semaine 3-4)

  • Unions & intersections, narrowing
  • Génériques (fonctions, classes, contraintes)
  • Classes & POO (public/private/protected/readonly)
  • Modules ES / CommonJS
  • tsconfig.json, ESLint, Prettier

📅 Phase 3 — Avancé (Semaine 5-6)

  • Utility Types : Partial, Pick, Omit, Record…
  • Types conditionnels & mapped types
  • Décorateurs (Angular, NestJS)
  • Gestion d'erreurs & typage strict

📅 Phase 4 — Écosystème (Semaine 7-8)

  • TypeScript avec React (props, hooks, events)
  • TypeScript avec Node.js / Express
  • Tests avec Jest + ts-jest
  • Vite / Webpack + TS
  • Publication d'un package npm typé
🎯 Projet final Application full-stack (API REST + front React) entièrement en TypeScript.

Exemples comparés

JavaScript

let nom = "Alice";
let mixte = [1, "deux", true]; // ✅ autorisé (mais risqué)

TypeScript

let nom: string = "Alice";
let mixte: (number | string)[] = [1, "deux"]; // ✅ typé
// let mixte2: number[] = [1, "deux"];        // ❌ Erreur

Inférence automatique

let nom = "Alice"; // TS comprend : string
nom = 42;          // ❌ Erreur

unknown — le any sécurisé

let data: unknown = "texte";
// data.toUpperCase(); // ❌ Interdit tant qu'on n'a pas vérifié
if (typeof data === "string") {
  data.toUpperCase(); // ✅ OK après narrowing
}

🔷 Fonctions

Paramètres typés

JavaScript

function saluer(nom, age) {
  return `Bonjour ${nom}, tu as ${age} ans`;
}
saluer();              // ⚠️ undefined partout
saluer("Alice", "30"); // ⚠️ age est une string

TypeScript

function saluer(nom: string, age: number): string {
  return `Bonjour ${nom}, tu as ${age} ans`;
}

saluer("Alice", 30);     // ✅
// saluer();              // ❌ Paramètres manquants
// saluer("Alice", "30"); // ❌ Mauvais type

Paramètres optionnels et par défaut

function saluer(nom: string, titre: string = "M."): string {
  return `${titre} ${nom}`;
}

function saluer2(nom: string, titre?: string): string {
  return titre ? `${titre} ${nom}` : nom;
}

Fonctions fléchées typées

const addition = (a: number, b: number): number => a + b;

// Callback typé
const nombres = [1, 2, 3];
nombres.map((n: number): number => n * 2);

Fonctions comme types

type Operation = (a: number, b: number) => number;

const somme: Operation = (a, b) => a + b;

function calculer(a: number, b: number, op: Operation): number {
  return op(a, b);
}
calculer(2, 3, somme); // 5

Surcharge (overloads)

function format(x: string): string;
function format(x: number): string;
function format(x: string | number): string {
  return typeof x === "string" ? x.toUpperCase() : x.toFixed(2);
}

format("abc");   // "ABC"
format(3.14159); // "3.14"
💡 Récapitulatif TS ajoute aux fonctions : typage des paramètres, type de retour, surcharges, this typé, callbacks typés.

🔷 Classes & POO

Modificateurs d'accès

ModificateurDans la classeHors classeHéritage
public (défaut)✅✅✅
protected✅❌✅
private✅❌❌

Paramètres de propriété (raccourci TS)

class Personne {
  constructor(
    public nom: string,
    public age: number,
    private id: number
  ) {}
}

Héritage

class Animal {
  constructor(public nom: string) {}
  crier(): void { console.log("..."); }
}

class Chien extends Animal {
  constructor(nom: string, public race: string) {
    super(nom);
  }
  crier(): void { console.log("Woof"); }
}

const c = new Chien("Rex", "Labrador");
c.crier(); // "Woof"

Classes abstraites

abstract class Forme {
  abstract aire(): number;

  decrire(): string {
    return `Aire : ${this.aire()}`;
  }
}

class Cercle extends Forme {
  constructor(private rayon: number) { super(); }
  aire(): number { return Math.PI * this.rayon ** 2; }
}

// const f = new Forme(); // ❌ Impossible (abstraite)

Interfaces & implémentation

interface Serializable {
  serialiser(): string;
}

class User implements Serializable {
  constructor(public nom: string, public age: number) {}
  serialiser(): string {
    return JSON.stringify({ nom: this.nom, age: this.age });
  }
}

Getters & Setters

class Temperature {
  private _celsius: number = 0;

  get celsius(): number { return this._celsius; }
  set celsius(v: number) {
    if (v < -273.15) throw new Error("Température invalide");
    this._celsius = v;
  }

  get fahrenheit(): number {
    return this._celsius * 9 / 5 + 32;
  }
}

Génériques dans les classes

class Stack<T> {
  private items: T[] = [];
  push(item: T): void { this.items.push(item); }
  pop(): T | undefined { return this.items.pop(); }
}

const s = new Stack<number>();
s.push(1);
// s.push("a"); // ❌ Erreur
⚠️ Attention private en TS est vérifié à la compilation uniquement. Pour un vrai privé runtime, utiliser #champ.

🔷 type vs interface

Critèreinterfacetype

Extension

// interface extends
interface Animal { nom: string; }
interface Chien extends Animal { race: string; }

// type intersection
type Animal = { nom: string };
type Chien = Animal & { race: string };

Déclaration fusionnée (interface uniquement)

interface User { nom: string; }
interface User { age: number; }
// Résultat : User = { nom: string; age: number }
💡 Règle pragmatique interface par défaut pour les objets, type quand interface ne peut pas faire le job (unions, tuples, mapped types).

🔷 Generics

Fonction générique

function identite<T>(valeur: T): T {
  return valeur;
}

identite<string>("hello"); // string
identite(42);              // number (inféré)

Contraintes (extends)

function longueur<T extends { length: number }>(x: T): number {
  return x.length;
}

longueur("abc");      // ✅
longueur([1, 2, 3]);  // ✅
// longueur(42);      // ❌ number n'a pas length

keyof + génériques

function getProp<T, K extends keyof T>(obj: T, cle: K): T[K] {
  return obj[cle];
}

const u = { nom: "Alice", age: 30 };
getProp(u, "nom"); // string
// getProp(u, "email"); // ❌

Génériques par défaut

interface Boite<T = string> {
  contenu: T;
}

const b1: Boite = { contenu: "hello" };        // T = string
const b2: Boite<number> = { contenu: 42 };

Classes génériques

class Stack<T> {
  private items: T[] = [];
  push(i: T) { this.items.push(i); }
  pop(): T | undefined { return this.items.pop(); }
}

🔷 Décorateurs

Un décorateur est une fonction qui modifie une classe, méthode, propriété ou paramètre à la définition. Très utilisés dans Angular, NestJS, TypeORM.

Activer dans tsconfig.json

{
  "compilerOptions": {
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true
  }
}

Décorateur de classe

function Component(config: { selector: string }) {
  return function (constructor: Function) {
    constructor.prototype.selector = config.selector;
  };
}

@Component({ selector: "app-user" })
class UserComponent {}

Décorateur de méthode

function Log(target: any, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  descriptor.value = function (...args: any[]) {
    console.log(`Appel de ${key}`, args);
    return original.apply(this, args);
  };
}

class Service {
  @Log
  fetch(id: number) { /* ... */ }
}

Exemple NestJS (cas réel)

@Controller("users")
export class UserController {
  constructor(private userService: UserService) {}

  @Get(":id")
  async findOne(@Param("id") id: string) {
    return this.userService.findOne(id);
  }
}

🔷 Async / Await

Typage du retour

interface User { id: number; nom: string; }

async function fetchUser(id: number): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  return res.json() as Promise<User>;
}
💡 À retenir async enveloppe toujours le retour dans un Promise<T>. Le type est inféré automatiquement.

Promise.all typé

const [users, posts] = await Promise.all([
  fetchUsers(),  // Promise<User[]>
  fetchPosts(),  // Promise<Post[]>
]);
// users: User[], posts: Post[]

Gestion d'erreurs

async function safeFetch<T>(url: string): Promise<T | null> {
  try {
    const res = await fetch(url);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.json() as T;
  } catch (e) {
    if (e instanceof Error) console.error(e.message);
    return null;
  }
}
⚠️ Piège catch (e) en TS strict : e est unknown. Il faut narrower avant usage.

Pièges courants

// ❌ Oublier await
async function bad() {
  const user = fetchUser(1); // Promise<User>, pas User
}

// ❌ async dans forEach
items.forEach(async (i) => { await traiter(i); }); // ne sera pas attendu

// ✅ for...of
for (const i of items) {
  await traiter(i);
}

Combinaisons utiles

// Parallèle (rapide)
await Promise.all(ids.map(id => fetchUser(id)));

// Premier arrivé
await Promise.race([fetchA(), fetchB()]);

// Tous, sans échec global
await Promise.allSettled([fetchA(), fetchB()]);
